## 核心原則

本網際網路應用程式介面之設計與開發，須遵循以下核心原則。

+ 範例程式驗證方式：邏輯檢查 ( 未經容器實測 )。
+ 對照環境版本：Python 3.14 ( 基底映像檔 `python:3.14-slim`，現行修補版本 3.14.7 )、FastAPI 0.141.1。

### I. 對外服務介面原則
應用程式介面以 HTTP 請求形式對外提供服務，所有服務能力皆可供遠端主機透過網路調用，例如 `curl http://[host-name]/api/exec`。

+ 伺服器於容器內以 `fastapi run` 啟動，監聽 IP 位址 `0.0.0.0`；不以僅監聽 `127.0.0.1` 之 `fastapi dev` 對外提供服務。
+ 容器內服務埠為 `80`，並以 `docker run -p 80:80` 發佈至主機 80 埠，遠端主機以不含埠號之網址存取服務。

**理由**：`fastapi run` 預設監聽 `0.0.0.0`，即主機所有可用 IP 位址，可供能與該主機通訊之遠端主機存取；`fastapi dev` 預設監聽 `127.0.0.1`，僅限本機存取。HTTP 網址未指定埠號時，預設使用 TCP 80 埠；調研描述之網址 `http://localhost/`、`http://[host-name]/api/exec` 皆未指定埠號，故服務埠與發佈埠採用 80。

**EXAMPLE**:
```bash
# 啟動容器，將主機 80 埠對應至容器 80 埠 ( 映像檔建置見原則 III )
docker run -d --name api-server -p 80:80 api-server

# 遠端主機經由網路調用服務，網址未指定埠號時使用 80 埠 ( 根路由見原則 VI )
curl http://[host-name]/
```

### II. Python 與 FastAPI 框架原則
伺服器端程式語言採用 Python，軟體框架採用 FastAPI。

+ 伺服器進入點 `server/main.py` 建立 `FastAPI` 類別之實例，並指派予變數 `app`。
+ 映像檔建置階段安裝 `fastapi[standard]`，並鎖定版本 `0.141.1`；`standard` 額外相依套件包含 `fastapi-cli[standard]` 與 `uvicorn[standard]`。
+ 伺服器以 FastAPI CLI 之 `fastapi run` 命令啟動。
+ Python 版本須符合 FastAPI 0.141.1 之要求 `>=3.10`。

**理由**：`app` 實例為建立所有 API 之主要互動點。以 `fastapi[standard]` 安裝 FastAPI 時，附帶可於終端機執行之命令列程式 FastAPI CLI；FastAPI CLI 預設嘗試之應用程式物件名稱為 `app` 與 `api`，並於內部使用 ASGI 伺服器 Uvicorn 執行應用程式。

### III. Docker 容器化與精簡映像原則
執行環境採用 Docker，基底映像檔採用 Docker 官方 Python 映像檔之 slim 變體。

+ 基底映像檔標籤標示 Python 版本：`python:3.14-slim`；不使用未標示版本之 `slim` 標籤。
+ 相依套件於建置階段以 `pip install --no-cache-dir` 安裝，安裝步驟置於複製程式碼步驟之前。
+ 容器內工作目錄為 `/app/api`，對應專案根目錄 `app/api`，僅複製 `server` 目錄與 `docker-entrypoint.sh`。
+ 容器進入點以 exec 形式指定：`ENTRYPOINT ["/app/api/docker-entrypoint.sh"]`。
+ Dockerfile 存放位置未於調研描述中指定；建置時以 `-f` 參數指定 Dockerfile 路徑，建置情境 ( build context ) 為 `app/api`。

**理由**：
+ slim 變體僅含執行 `python` 所需之最小 Debian 套件；Docker 文件建議選用符合需求之最小基底映像檔，以縮減映像檔體積並減少相依套件帶入之弱點。
+ slim 變體不含編譯其他語言擴充模組所需之 Debian 套件；相依套件僅提供原始碼發行檔時 `pip install` 可能失敗，此情形須於 `pip install` 前安裝所需 Debian 套件。
+ 官方 Python 映像檔之 `slim` 標籤現行與 `3.14.7-slim`、`3.14-slim`、`3-slim` 同屬一個映像檔，發布者可將標籤更新指向新映像檔；標示 Python 版本可固定基底映像檔之 Python 次要版本。
+ `--no-cache-dir` 使 pip 不於映像檔內保存下載之套件；相依套件安裝步驟置於複製程式碼之前，程式碼變更時可沿用 Docker 建置快取。
+ exec 形式之 `ENTRYPOINT` 不經由命令 shell 啟動，為 Dockerfile 參考文件所列之偏好形式。

**EXAMPLE**:
```dockerfile
# 建置情境 ( build context )：app/api
FROM python:3.14-slim

WORKDIR /app/api

# Install server dependencies
RUN pip install --no-cache-dir "fastapi[standard]==0.141.1"

# Copy server project and entrypoint script
COPY server ./server
COPY docker-entrypoint.sh ./docker-entrypoint.sh
RUN chmod +x ./docker-entrypoint.sh

ENTRYPOINT ["/app/api/docker-entrypoint.sh"]
```
```bash
# 建置映像檔，<Dockerfile 路徑> 為 Dockerfile 之實際存放路徑
docker build -f <Dockerfile 路徑> -t api-server app/api
```

### IV. 專案結構標準化原則
應用程式介面專案根目錄為 `app/api`，目錄與檔案配置如下。

+ `server`：伺服器專案目錄。
  - `routes`：路由目錄，每個路由為一個子目錄。
  - `service`：共用服務目錄。
  - `main.py`：伺服器進入點。
+ `docker-entrypoint.sh`：執行環境進入點腳本。
+ `routes`、`routes` 下之各路由目錄與 `service` 設置 `__init__.py`，作為 Python 套件。
+ `server` 目錄不設置 `__init__.py`。

**理由**：
+ Python 將含 `__init__.py` 之目錄視為套件 ( 命名空間套件除外 )。
+ FastAPI CLI 自指定檔案所在目錄向上逐層檢查 `__init__.py`，將最上層套件目錄之上一層目錄加入 `sys.path`，並據此組成模組匯入名稱。`server` 未設置 `__init__.py` 時，加入 `sys.path` 者為 `server` 目錄，`main.py` 以模組名稱 `main` 匯入，`main.py` 內之 `from routes import asa` 可解析；`server` 設置 `__init__.py` 時，加入 `sys.path` 者為 `app/api` 目錄，模組名稱為 `server.main`，`from routes import asa` 無法解析。

**EXAMPLE**:
```
app/api
├── server
│   ├── routes
│   │   ├── __init__.py
│   │   └── asa
│   │       └── __init__.py
│   ├── service
│   │   └── __init__.py
│   └── main.py
└── docker-entrypoint.sh
```

### V. 執行環境進入點腳本原則
`app/api/docker-entrypoint.sh` 為容器進入點腳本，負責啟動伺服器。

+ 腳本切換至腳本所在目錄 ( `app/api` ) 後，以 `exec` 執行 `fastapi run server/main.py --port 80`。
+ 伺服器程序以 `exec` 取代腳本之 shell 程序，成為容器之 PID 1。
+ 使用正式環境模式之 `fastapi run` ( 自動重新載入停用 )，不使用開發模式之 `fastapi dev`。

**理由**：
+ 以 shell 形式 ( `/bin/sh -c` ) 啟動之程序不是容器之 PID 1，不會接收 Unix 訊號，亦不會收到 `docker stop` 發送之 `SIGTERM`；啟動腳本以 `exec` 執行最終程式，可使該程式接收 Unix 訊號。
+ FastAPI 文件要求容器啟動命令採用 exec 形式，以確保 FastAPI 正常關閉並觸發生命週期 ( lifespan ) 事件。
+ `fastapi dev` 之自動重新載入僅供開發使用；`fastapi run` 為容器等正式環境之執行方式。

**EXAMPLE**:
```sh
#!/bin/sh
# app/api/docker-entrypoint.sh
set -e

# 切換至腳本所在目錄 ( app/api )
cd "$(dirname "$0")"

# 以 exec 取代目前 shell 程序，使伺服器成為容器 PID 1
exec fastapi run server/main.py --port 80
```

### VI. 根路由原則
根路由 `/` 於伺服器進入點 `server/main.py` 直接定義，回應伺服器資訊，例如 `http://localhost/`。

+ 以路徑操作裝飾器 `@app.get("/")` 宣告處理 `GET /` 請求之函式 `show_fastapi_information`。
+ 回應內容：`Server` 欄位值為 `"FastAPI Server"`；`Version` 欄位值為 `fastapi.__version__`，以別名 `fastapi_version` 匯入。
+ `app = FastAPI()` 宣告於 `@app.get("/")` 之前。

**理由**：路徑操作函式回傳之 `dict` 由 FastAPI 自動轉換為 JSON 回應。`fastapi.__version__` 為 FastAPI 套件定義之版本字串，0.141.1 版之值為 `"0.141.1"`。調研描述之根路由程式片段未包含 `app` 之宣告，裝飾器 `@app.get("/")` 執行前須已存在 `app` 實例。

**EXAMPLE**:
```python
# app/api/server/main.py
# Import server libraries
from fastapi import FastAPI
from fastapi import __version__ as fastapi_version

# Configuration server
app = FastAPI()

# Configuration server root route
@app.get("/")
def show_fastapi_information():
    return {"Server": "FastAPI Server", "Version": f"{fastapi_version}"}
```
```bash
# 回應 JSON 內容：{"Server": "FastAPI Server", "Version": "0.141.1"}
curl http://localhost/
```

### VII. 子路由目錄化與套件掛載原則
每個子路由以 `server/routes` 下之目錄形式結構化，並以套件形式掛載至服務，例如 `http://localhost/asa`。

+ 子路由套件於 `__init__.py` 建立獨立之 `FastAPI` 應用程式實例並指派予名稱 `module`，路徑操作宣告於 `module`。
+ 伺服器進入點以 `from routes import asa` 匯入子路由套件，並以 `app.mount("/asa", asa.module)` 掛載；調研描述之範例中，套件 `routes/asa` 掛載於路徑 `/asa`。
+ 子應用程式具備獨立之 OpenAPI 與文件介面：主應用程式文件 `/docs` 僅列出主應用程式之路徑操作，子應用程式文件位於 `/asa/docs`。
+ 請求 `http://localhost/asa` ( 無結尾斜線 ) 時，伺服器回應 HTTP 307 並重新導向至 `http://localhost/asa/`；以 `curl` 調用時加上 `-L` 選項跟隨重新導向，或直接請求 `http://localhost/asa/`。

**理由**：
+ 掛載 ( mount ) 係於指定路徑加入一個獨立應用程式，由該應用程式處理此路徑下之所有請求；FastAPI 以 ASGI 規格之 `root_path` 機制告知子應用程式其掛載路徑，子應用程式之文件介面據此使用路徑前綴 `/asa`。
+ `from package import item` 之 `item` 可為套件之子模組 ( 或子套件 )；`from routes import asa` 據此匯入 `routes/asa` 套件，`asa.module` 為其 `__init__.py` 定義之名稱。
+ FastAPI 之 `mount` 方法繼承自 Starlette；Starlette 之 `Mount` 以掛載路徑加上 `/{path:path}` 編譯比對規則，`/asa` 不符合以 `/asa/` 開頭之規則。FastAPI 之 `redirect_slashes` 預設為 `True`，無相符路由時，路由器以加上結尾斜線之路徑重新比對，相符即回應 `RedirectResponse`，其預設狀態碼為 307。

**EXAMPLE**:
```python
# app/api/server/routes/asa/__init__.py
# Import server libraries
from fastapi import FastAPI

# Configuration route module
module = FastAPI()

# Configuration route root path
@module.get("/")
def show_asa_information():
    return {"Route": "asa"}
```
```python
# app/api/server/main.py
# Import server libraries
from fastapi import FastAPI
from fastapi import __version__ as fastapi_version

# Import server modules
from routes import asa

# Configuration server
app = FastAPI()

# Configuration server root route
@app.get("/")
def show_fastapi_information():
    return {"Server": "FastAPI Server", "Version": f"{fastapi_version}"}

# Configuration server sub route
app.mount("/asa", asa.module)
```
```bash
# 無結尾斜線：回應狀態碼 307，Location 標頭為 http://localhost/asa/
curl -i http://localhost/asa

# 跟隨重新導向，回應 JSON 內容：{"Route": "asa"}
curl -L http://localhost/asa
```
