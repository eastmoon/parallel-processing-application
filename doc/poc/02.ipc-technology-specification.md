## 通訊機制技術規範

本規範定義行程間通訊 ( Inter-process communication, IPC ) 所採用之通訊機制，以及各機制發送、接收訊息之實作規則。各機制之發送、接收特性如下：

| 機制 | 模組 / 介面 | 訊息邊界 | 資料型別 | 就緒通知 | 結束偵測 |
| --- | --- | --- | --- | --- | --- |
| 共享記憶體 | `multiprocessing.shared_memory.SharedMemory` | 無，須自訂長度標頭 | 位元組緩衝區 ( `memoryview` ) | 無，須搭配 `Semaphore` 等同步原語 | 無，須自訂結束訊號 |
| 管道 | `multiprocessing.Pipe` | 保留，一次 `send()` 對應一次 `recv()` | 可 pickle 之物件、位元組 | `recv()` 阻塞、`poll(timeout)` | `recv()` 拋出 `EOFError` |
| Socket ( TCP ) | `socket` | 無，須自訂長度標頭 | 位元組 | `recv()` 阻塞、`settimeout()` | `recv()` 回傳 `b""` |

### I. 共享記憶體 (Shared Memory)

+ 須以 Python `multiprocessing.shared_memory.SharedMemory` 實作。
+ 建立與連接：
  - 發送端以 `SharedMemory(create=True, size=容量)` 建立區塊，並將 `name` 屬性傳遞給接收端。
  - 接收端以 `SharedMemory(name=name)` 連接既有區塊。
  - 區塊容量於建立時固定；訊息 ( 含標頭 ) 超過容量時，發送端須拒絕寫入。
+ 訊息格式：
  - 區塊僅提供位元組緩衝區 ( `buf`，型別為 `memoryview` )，不記錄訊息長度與邊界。
  - 發送端須先以 `struct` 寫入固定長度之長度標頭，再寫入訊息內容。
  - 接收端須依標頭長度讀取，不以 `size` 屬性推斷訊息長度 ( 連接端取得之 `size` 可能因分頁對齊而大於建立時指定之容量 )。
  - 接收端須立即將讀取內容複製為 `bytes`，再通知發送端可寫入下一則訊息。
+ 發送、接收之同步：
  - 區塊本身不提供「已寫入」、「已讀取」通知，須搭配 `multiprocessing.Semaphore` 交握：
    - `empty` ( 初始值 1 ) 表示區塊可寫入；`full` ( 初始值 0 ) 表示區塊存有未讀訊息。
    - 發送端：`empty.acquire()` → 寫入 → `full.release()`。
    - 接收端：`full.acquire()` → 讀取並複製 → `empty.release()`。
  - 等待須設定逾時 ( `acquire(timeout=...)` )；回傳 `False` 時視為對端未回應。
  - 發送結束時，發送端須寫入約定之結束訊號 ( 例：長度標頭 `-1` )。
+ 資源釋放：
  - 各端使用完畢須呼叫 `close()`；`close()` 前須釋放所有由 `buf` 切出之 `memoryview`，否則拋出 `BufferError`。
  - 建立端須於接收端結束後方可呼叫 `close()`，並呼叫 `unlink()` 一次；連接端不呼叫 `unlink()`。
  - Windows 平台於區塊之所有代號 ( handle ) 關閉後即釋放區塊，`unlink()` 於 Windows 無作用；建立端提前 `close()` 將使接收端無法連接。

**Rationale**: 共享記憶體區塊為多個行程對映之同一段位元組緩衝區，不具訊息邊界、就緒通知與結束偵測，故發送、接收訊息之機制須由長度標頭、`Semaphore` 交握與結束訊號組成；區塊生命週期跨越多個行程，故明定 `close()`、`unlink()` 之呼叫責任與時機。

**EXAMPLE**:
```python
import struct
from multiprocessing import Process, Semaphore
from multiprocessing.shared_memory import SharedMemory

CAPACITY = 1024                  # 區塊容量 ( 位元組 )
HEADER = struct.Struct("!i")     # 4 位元組長度標頭
END = -1                         # 結束訊號
TIMEOUT = 5.0                    # 等待逾時 ( 秒 )


def write_message(buf, payload):
    """寫入長度標頭與內容；payload 為 None 時寫入結束訊號。"""
    if payload is None:
        HEADER.pack_into(buf, 0, END)
        return
    if HEADER.size + len(payload) > len(buf):
        raise ValueError("message exceeds shared memory capacity")
    HEADER.pack_into(buf, 0, len(payload))
    buf[HEADER.size:HEADER.size + len(payload)] = payload


def read_message(buf):
    """依長度標頭讀取內容並複製為 bytes；收到結束訊號時回傳 None。"""
    (length,) = HEADER.unpack_from(buf, 0)
    if length == END:
        return None
    if length < 0 or HEADER.size + length > len(buf):
        raise ValueError("invalid message length")
    return bytes(buf[HEADER.size:HEADER.size + length])


def send(shm, empty, full, payload):
    if not empty.acquire(timeout=TIMEOUT):       # 等待「可寫入」
        raise TimeoutError("receiver did not respond")
    write_message(shm.buf, payload)
    full.release()                               # 通知「已寫入」


def receiver(name, empty, full):
    shm = SharedMemory(name=name)                # 以名稱連接既有區塊
    try:
        while True:
            if not full.acquire(timeout=TIMEOUT):    # 等待「已寫入」
                raise TimeoutError("sender did not respond")
            message = read_message(shm.buf)
            empty.release()                      # 通知「已讀取」
            if message is None:
                break
            print("received:", message)
    finally:
        shm.close()                              # 連接端僅 close()


if __name__ == "__main__":
    shm = SharedMemory(create=True, size=CAPACITY)   # 發送端建立區塊
    empty, full = Semaphore(1), Semaphore(0)
    try:
        p = Process(target=receiver, args=(shm.name, empty, full))
        p.start()
        for payload in (b"hello", b"world"):
            send(shm, empty, full, payload)
        send(shm, empty, full, None)             # 結束訊號
        p.join()
    finally:
        shm.close()
        shm.unlink()                             # 建立端於接收端結束後 unlink() 一次
```

**檢查方式**: 邏輯檢查 ( 未實際執行 )；撰寫基準：Python 3.8 以上標準函式庫。

### II. 管道 (Pipes)

+ 須以 Python `multiprocessing.Pipe` 實作。
+ 建立：
  - `Pipe()` 回傳一對 `Connection`；`duplex=True` ( 預設 ) 時兩端皆可收發。
  - `Pipe(duplex=False)` 回傳 `(conn1, conn2)`，`conn1` 僅能接收、`conn2` 僅能發送。
+ 發送、接收介面：
  - `send(obj)` 以 pickle 序列化物件後傳送，物件須可被 pickle；`recv()` 接收並反序列化一則完整訊息。
  - 一次 `send()` 對應一次 `recv()`，訊息邊界與發送順序保留。
  - 位元組資料可使用 `send_bytes()` / `recv_bytes()`，不經 pickle；收發兩端須使用成對之方法。
  - 單則訊息 pickle 後過大 ( 約 32 MiB 以上，依作業系統而異 ) 時，`send()` 可能拋出 `ValueError`；大量資料須分段傳送。
+ 阻塞與逾時：
  - `recv()` 於無資料時阻塞。
  - 需限制等待時間時，以 `poll(timeout)` 確認是否有資料可讀；回傳 `False` 表示逾時內無資料。
+ 結束偵測：
  - 發送端傳送完畢須呼叫 `close()`。
  - 對端之 `Connection` 全部關閉且無剩餘資料時，`recv()` 拋出 `EOFError`。
  - 父行程於 `Process.start()` 後須關閉交付子行程之 `Connection` 副本；未關閉時對端未全部關閉，`recv()` 持續阻塞而不拋出 `EOFError`。
+ 並行與安全：
  - 同一端 `Connection` 不可由多個行程或執行緒同時讀取或寫入 ( 資料可能損毀 )。
  - `recv()` 會自動以 pickle 反序列化，反序列化過程可執行資料所指定之可呼叫物件；`Connection` 僅可與可信任之行程交換資料。

**Rationale**: `Connection` 以訊息為單位收發，並以 `EOFError` 表示對端關閉，但該偵測僅於對端所有副本皆關閉時成立，故明定收發介面與關閉責任；`recv()` 自動反序列化，故限定資料來源。

**EXAMPLE**:
```python
from multiprocessing import Pipe, Process


def sender(conn, messages):
    try:
        for message in messages:
            conn.send(message)               # pickle 序列化後傳送，一次一則
    finally:
        conn.close()                         # 傳送完畢關閉，接收端據以取得 EOFError


if __name__ == "__main__":
    recv_conn, send_conn = Pipe(duplex=False)    # ( 僅能接收, 僅能發送 )
    p = Process(target=sender, args=(send_conn, [b"hello", {"id": 1}]))
    p.start()
    send_conn.close()                        # 父行程關閉交付子行程之發送端副本
    try:
        while True:
            try:
                message = recv_conn.recv()   # 阻塞至取得一則完整訊息
            except EOFError:                 # 發送端已全部關閉且無剩餘資料
                break
            print("received:", message)
    finally:
        recv_conn.close()
        p.join()
```

### III. Socket (本機網路 0.0.0.0)

+ 須以 Python `socket` 模組實作，位址族別為 `AF_INET`，型別為 `SOCK_STREAM` ( TCP )。
+ 接收端 ( 伺服端 )：
  - 須綁定 `("0.0.0.0", port)`；`0.0.0.0` 表示本機所有 IPv4 介面，loopback 與對外網路介面皆接受連線。
  - `listen()` 後以 `accept()` 取得連線專用之 socket，並以該 socket 收發訊息。
  - `port` 為 `0` 時由作業系統分配可用埠號，須以 `getsockname()[1]` 取得實際埠號並告知發送端。
+ 發送端 ( 用戶端 )：
  - `0.0.0.0` 僅作為綁定位址；發送端須連線至具體位址，本機行程間使用 `127.0.0.1`。
+ 訊息邊界：
  - TCP 為位元組串流，不保留單次 `send()` / `sendall()` 之邊界；單次 `recv()` 可能取得部分訊息，或多則訊息合併之資料。
  - 每則訊息須以固定長度之長度標頭 ( 例：`struct.Struct("!I")` ) 界定。
+ 發送：
  - `send()` 回傳實際送出之位元組數，可能小於資料長度；須使用 `sendall()` 送出完整資料。
+ 接收：
  - `recv(n)` 至多回傳 `n` 位元組；須迴圈呼叫 `recv()` 至取得標頭指定之長度。
  - `recv()` 回傳 `b""` 表示對端已關閉連線；於訊息邊界取得 `b""` 視為正常結束，於訊息中途取得 `b""` 視為連線中斷。
  - 須以 `settimeout()` 限制等待時間；逾時拋出 `socket.timeout`。
+ 資料格式：
  - 訊息內容為位元組；物件須由應用層序列化 ( 例：`json` )。
  - 綁定 `0.0.0.0` 時對外網路介面亦接受連線，不可對接收之資料使用 `pickle` 反序列化。
+ 資源釋放：以 `with` 陳述式確保 socket 關閉。

**Rationale**: TCP 僅提供位元組串流，不具訊息邊界，且單次 `send()` / `recv()` 不保證處理完整資料，故發送、接收訊息之機制須由長度標頭、`sendall()` 與迴圈接收組成；綁定 `0.0.0.0` 時所有 IPv4 介面皆接受連線，故明定連線目標位址與接收資料之解析限制。

**EXAMPLE**:
```python
import socket
import struct
from multiprocessing import Process

HEADER = struct.Struct("!I")     # 4 位元組長度標頭 ( 網路位元組順序 )
TIMEOUT = 5.0                    # 等待逾時 ( 秒 )


def send_message(sock, payload):
    sock.sendall(HEADER.pack(len(payload)) + payload)    # sendall() 送出完整資料


def recv_exact(sock, size):
    """迴圈呼叫 recv() 至取得 size 位元組；對端中途關閉時拋出 ConnectionError。"""
    chunks = []
    while size > 0:
        chunk = sock.recv(size)
        if not chunk:
            raise ConnectionError("connection closed in the middle of a message")
        chunks.append(chunk)
        size -= len(chunk)
    return b"".join(chunks)


def recv_message(sock):
    """讀取一則訊息；對端於訊息邊界關閉連線時回傳 None。"""
    first = sock.recv(HEADER.size)
    if not first:                                # b"" 表示對端已關閉
        return None
    header = first + recv_exact(sock, HEADER.size - len(first))
    (length,) = HEADER.unpack(header)
    return recv_exact(sock, length)


def sender(port, messages):
    with socket.create_connection(("127.0.0.1", port), timeout=TIMEOUT) as sock:
        for payload in messages:
            send_message(sock, payload)
    # 離開 with 區塊時關閉連線，接收端 recv() 取得 b""


if __name__ == "__main__":
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
        server.bind(("0.0.0.0", 0))              # 本機所有 IPv4 介面；埠號由系統分配
        server.listen()
        server.settimeout(TIMEOUT)
        port = server.getsockname()[1]           # 實際埠號，告知發送端
        p = Process(target=sender, args=(port, [b"hello", b"world"]))
        p.start()
        conn, addr = server.accept()             # 連線專用 socket
        with conn:
            conn.settimeout(TIMEOUT)             # recv() 逾時拋出 socket.timeout
            while True:
                message = recv_message(conn)
                if message is None:
                    break
                print("received:", message, "from", addr)
        p.join()
```
