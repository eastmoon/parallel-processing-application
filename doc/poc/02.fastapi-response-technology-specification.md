## Response Structure Design

本規範定義行程間以 HTTP 協定通訊時，服務端以 FastAPI 建構之網際網路服務之回應結構，涵蓋常見的回應格式（成功 200、錯誤 400），以及裝飾函數參數 `response_model`、`response_class` 之設計方式與選用時機。

**技術堆疊**

| 項目 | 規格 |
| --- | --- |
| 程式語言 | Python；FastAPI 0.141.1 之套件需求為 Python >=3.10，範本驗證版本為 3.13.7 |
| Web 框架 | FastAPI 0.141.1 |
| 資料模型 | Pydantic 2.13.5（v2 API：`model_validate`、`model_dump`、`model_dump_json`） |
| ASGI 框架 | Starlette 1.7.0（FastAPI 相依套件，提供 Response 類別與例外處理機制） |
| ASGI 伺服器 | Uvicorn 0.54.0 |
| 範本驗證 | `fastapi.testclient.TestClient`（相依 httpx2 2.13.1；Starlette 文件標示以 httpx 搭配 TestClient 已棄用） |

**適用範圍**

+ 以 FastAPI 裝飾函數（`@app.get`、`@app.post`、`@router.put` 等）宣告之所有路由。
+ JSON 回應本體之結構、非 JSON 路由之錯誤回應結構，以及回應結構於 OpenAPI 文件之宣告。

**名詞定義**

+ 信封（Envelope）：包覆回應資料之固定外層結構。
+ 成功回應：HTTP 200，`success` 為 `true` 之信封。
+ 錯誤回應：HTTP 400（及其他 4xx、5xx），`success` 為 `false` 之信封。
+ 對外模型：僅列出允許輸出欄位之 Pydantic 模型（範本中之 `TaskOut`）。
+ 內部欄位：僅供服務內部使用、不得輸出之欄位（範本中之 `worker_token`）。
+ 錯誤契約：以裝飾函數之 `responses` 參數宣告、僅用於 OpenAPI 文件之錯誤回應結構（範本中之 `ERROR_RESPONSES`）。
+ Pydantic 直接序列化：路由宣告回應模型（`response_model` 或回傳型別註記）且未宣告 `response_class` 時，FastAPI 以 Pydantic 產生 JSON 位元組並直接回應之輸出路徑（FastAPI 0.130.0 起）。

### I. Common Response Envelope（常見的回應格式）

所有 JSON 回應以固定信封輸出。成功回應（HTTP 200）與錯誤回應（HTTP 400）以 `success` 欄位判別，`code` 欄位等於 HTTP 狀態碼；FastAPI 預設之錯誤格式由全域例外處理器轉換為錯誤信封。信封之欄位設計對照下列常見格式。

**常見格式比較**

| 格式 | 成功回應 | 錯誤回應 | 狀態碼於本體之表示 | 錯誤明細 |
| --- | --- | --- | --- | --- |
| JSend | `status` 為 `"success"`，資料置於 `data`；無資料時 `data` 為 `null` | `status` 為 `"fail"`（送出之資料有問題或前置條件未滿足），說明置於 `data`；`status` 為 `"error"`（處理請求時拋出例外），必要 `message`，選填 `code`、`data` | `error` 之選填 `code`（錯誤對應之數值代碼） | `fail` 之 `data`，例如 `{"title": "A title is required"}` |
| RFC 9457 Problem Details | 不適用（僅定義錯誤之 problem detail） | 成員 `type`、`title`、`status`、`detail`、`instance` | `status`：僅供參考，產生者必須於實際 HTTP 回應使用相同狀態碼 | 問題類型之擴充成員，例如 `errors` 陣列（`detail`、`pointer`） |
| JSON:API | 頂層 `data` | 頂層 `errors` 陣列；`data` 與 `errors` 不得並存於同一文件 | 錯誤物件之 `status`（字串） | 錯誤物件之 `code`、`title`、`detail`、`source`（`pointer`、`parameter`、`header`） |
| 本規範 | `success` 為 `true`，含 `code`、`message`、`data` | `success` 為 `false`，含 `code`、`message`、`errors` | `code`（整數，等於 HTTP 狀態碼） | `errors[]` 之 `field`、`type`、`message` |

媒體型別：RFC 9457 定義 `application/problem+json`；JSON:API 規定以 `application/vnd.api+json` 傳送；本規範沿用 FastAPI 預設之 `application/json`。

**成功回應（HTTP 200）**

```json
{
  "success": true,
  "code": 200,
  "message": "OK",
  "data": {"task_id": 1, "name": "resize-images", "status": "running", "priority": 3}
}
```

**錯誤回應（HTTP 400）**

```json
{
  "success": false,
  "code": 400,
  "message": "Request validation failed",
  "errors": [
    {"field": "path.task_id", "type": "greater_than_equal", "message": "Input should be greater than or equal to 1"}
  ]
}
```

**欄位定義**

| 欄位 | 型別 | 成功回應 | 錯誤回應 | 說明 |
| --- | --- | --- | --- | --- |
| `success` | boolean | `true` | `false` | 判別欄位 |
| `code` | integer | `200` | `400` | 等於 HTTP 狀態碼 |
| `message` | string | `"OK"` | 錯誤摘要 | 人類可讀之摘要 |
| `data` | object／null | 必要 | 不出現 | 回應資料 |
| `errors` | array | 不出現 | 必要，至少一筆 | 錯誤明細 |

| `errors[]` 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `field` | string／null | 錯誤位置，以 `.` 串接來源與欄位（`body.name`、`path.task_id`、`query.limit`）；非欄位錯誤為 `null` |
| `type` | string | 機器可讀之錯誤類型（`missing`、`greater_than_equal`、`duplicate`、`http_error` 等） |
| `message` | string | 人類可讀之錯誤說明 |

**狀態碼對照**

| HTTP 狀態碼 | 發生條件 | 信封 |
| --- | --- | --- |
| 200 | 處理成功 | `SuccessResponse` |
| 400 | 請求驗證失敗（`RequestValidationError`，含 JSON 解析失敗）、業務規則錯誤（`ApiError`） | `ErrorResponse` |
| 404、405 等 4xx | `HTTPException`（含 Starlette 路由產生者） | `ErrorResponse` |
| 500 | 未預期例外、回應驗證失敗（`ResponseValidationError`） | `ErrorResponse` |

**鐵律**

1. JSON 回應本體必須為信封物件，不得回傳未包覆之陣列、字串或數值。
2. 成功回應必須包含且僅包含 `success`、`code`、`message`、`data` 四個欄位。
3. 錯誤回應必須包含且僅包含 `success`、`code`、`message`、`errors` 四個欄位；`data` 與 `errors` 不得並存。
4. `success` 於 2xx 為 `true`，於 4xx／5xx 為 `false`；不得出現 HTTP 200 搭配 `success: false` 之回應。
5. `code` 必須等於實際 HTTP 狀態碼；業務錯誤之分類以 `errors[].type` 表達，不得另以 `code` 表達。
6. `data` 欄位不得省略，無資料時值為 `null`；列表資料以物件包覆，列表置於 `items` 欄位（例如 `{"items": [...], "total": 2}`）。
7. `errors` 至少包含一筆，每筆必須包含 `field`、`type`、`message`。
8. 請求驗證失敗（`RequestValidationError`）必須轉換為 HTTP 400 錯誤回應，取代 FastAPI 預設之 HTTP 422 與 `{"detail": [...]}` 結構。
9. 業務規則錯誤以 `ApiError` 拋出，由例外處理器轉換為 HTTP 400 錯誤回應；路由處理函式不得自行組裝錯誤本體。
10. HTTP 例外處理器必須註冊於 Starlette 之 `HTTPException`（`starlette.exceptions.HTTPException`），以涵蓋 FastAPI 之 `HTTPException` 與 Starlette 內部產生之 404、405；`code` 對應實際狀態碼，並保留例外所附之回應標頭（例如 `Allow`、`WWW-Authenticate`）。
11. 未預期例外轉換為 HTTP 500 錯誤回應，`message` 固定為 `Internal Server Error`，不得輸出堆疊、SQL、檔案路徑等內部資訊。
12. 欄位名稱採 snake_case；JSON 回應之 `Content-Type` 為 `application/json`，本體以 UTF-8 編碼。
13. 信封模型（`SuccessResponse`、`ErrorResponse`、`ErrorDetail`）、錯誤契約（`ERROR_RESPONSES`）與例外處理器集中定義於共用模組，各應用程式以 `register_exception_handlers(app)` 註冊，不得於各服務重複定義。

**理由**

+ 固定信封使呼叫端行程以單一流程解析回應：先讀取 `success` 判別（對應 JSend 之 `status`），再讀取 `data` 或 `errors`。
+ RFC 9457 之 `status` 成員僅供參考，且產生者必須於實際 HTTP 回應使用相同狀態碼；`code` 採相同約束，使回應本體脫離 HTTP 傳輸層（寫入日誌、轉送至訊息佇列）後仍保留狀態資訊。
+ JSend 規定無資料時 `data` 設為 `null`；鐵律 6 採相同處理，`data` 之存在與否不隨資料有無變動。
+ JSON:API 規定錯誤物件以頂層 `errors` 陣列回傳，且 `data` 與 `errors` 不得並存；RFC 9457 之擴充成員範例亦以 `errors` 陣列列出多筆欄位錯誤。單次請求之多個欄位錯誤可一次回報。
+ MDN 對 400 之定義為伺服器認為屬用戶端錯誤而不處理請求，對 422 之定義為伺服器理解請求內容之型別且語法正確，但無法處理其中之指示。本規範依調研描述之正確（200）與錯誤（400）兩類回應，將 FastAPI 預設之 HTTP 422 `{"detail": [...]}`（Docker 實測）統一轉換為 400 錯誤信封，用戶端僅需處理單一錯誤結構。
+ FastAPI 之 `HTTPException` 繼承自 Starlette 之 `HTTPException`；FastAPI 文件說明例外處理器註冊於 Starlette 之 `HTTPException` 時，可處理 Starlette 內部程式碼、擴充套件或外掛拋出之例外。
+ RFC 9457 之安全性考量建議避免經 HTTP 介面提供堆疊等實作細節。Starlette 將 `Exception`（或 500）處理器交由 `ServerErrorMiddleware` 呼叫，送出回應後仍重新拋出例外，供伺服器記錄錯誤。
+ 列表資料以物件包覆，新增分頁欄位（`total`、`next_cursor`）時不改變 `data` 之型別。

**EXAMPLE**:

驗證：Docker 實測（環境版本見〈驗證方式〉），對應檔案 `src/envelope.py`。

```python
"""envelope.py：常見回應格式之共用模組（成功 200／錯誤 400）。

執行：python envelope.py
相依：pip install "fastapi==0.141.1"
"""
from collections.abc import Mapping
from typing import Any, Generic, Literal, TypeVar

from fastapi import FastAPI, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from pydantic import BaseModel, Field
from starlette.exceptions import HTTPException as StarletteHTTPException

T = TypeVar("T")


class ErrorDetail(BaseModel):
    """錯誤明細（errors[] 之單筆項目）。"""

    field: str | None = Field(default=None, description="錯誤位置，以 . 串接；非欄位錯誤為 null")
    type: str = Field(description="機器可讀之錯誤類型")
    message: str = Field(description="人類可讀之錯誤說明")


class SuccessResponse(BaseModel, Generic[T]):
    """成功回應信封（2xx）。"""

    success: Literal[True] = True
    code: int = Field(default=200, ge=200, le=299)
    message: str = "OK"
    data: T


class ErrorResponse(BaseModel):
    """錯誤回應信封（4xx／5xx）。"""

    success: Literal[False] = False
    code: int = Field(default=400, ge=400, le=599)
    message: str = "Bad Request"
    errors: list[ErrorDetail] = Field(min_length=1)


# 錯誤契約（僅用於 OpenAPI 文件，不參與執行期驗證）；宣告 4XX 後 FastAPI 不再自動加入 422 文件
ERROR_RESPONSES: dict[int | str, dict[str, Any]] = {
    400: {"model": ErrorResponse, "description": "Bad Request"},
    "4XX": {"model": ErrorResponse, "description": "Client Error"},
    "5XX": {"model": ErrorResponse, "description": "Server Error"},
}


class ApiError(Exception):
    """業務規則錯誤；由例外處理器轉換為錯誤信封。"""

    def __init__(
        self,
        message: str,
        errors: list[ErrorDetail] | None = None,
        status_code: int = 400,
    ) -> None:
        super().__init__(message)
        self.message = message
        self.errors = errors or [ErrorDetail(type="bad_request", message=message)]
        self.status_code = status_code


def ok(data: Any = None, *, message: str = "OK", code: int = 200) -> dict[str, Any]:
    """組裝成功信封；實際輸出結構由 response_model 驗證與過濾。"""
    return {"success": True, "code": code, "message": message, "data": data}


def error_response(
    status_code: int,
    message: str,
    errors: list[ErrorDetail],
    headers: Mapping[str, str] | None = None,
) -> JSONResponse:
    """組裝錯誤信封；code 欄位等於 HTTP 狀態碼。"""
    body = ErrorResponse(code=status_code, message=message, errors=errors)
    return JSONResponse(status_code=status_code, content=body.model_dump(mode="json"), headers=headers)


def register_exception_handlers(app: FastAPI) -> None:
    """註冊全域例外處理器，使所有錯誤皆以錯誤信封輸出。"""

    @app.exception_handler(ApiError)
    async def handle_api_error(request: Request, exc: ApiError) -> JSONResponse:
        return error_response(exc.status_code, exc.message, exc.errors)

    @app.exception_handler(RequestValidationError)
    async def handle_validation_error(request: Request, exc: RequestValidationError) -> JSONResponse:
        # 取代 FastAPI 預設之 422 {"detail": [...]}，統一為 400 錯誤信封
        errors = [
            ErrorDetail(
                field=".".join(str(part) for part in err["loc"]) or None,
                type=err["type"],
                message=err["msg"],
            )
            for err in exc.errors()
        ]
        return error_response(400, "Request validation failed", errors)

    @app.exception_handler(StarletteHTTPException)
    async def handle_http_exception(request: Request, exc: StarletteHTTPException) -> JSONResponse:
        # 註冊於 Starlette 之 HTTPException：涵蓋 FastAPI HTTPException 與 Starlette 路由產生之 404、405
        message = str(exc.detail)
        errors = [ErrorDetail(type="http_error", message=message)]
        return error_response(exc.status_code, message, errors, headers=exc.headers)

    @app.exception_handler(Exception)
    async def handle_unexpected_error(request: Request, exc: Exception) -> JSONResponse:
        # 由 ServerErrorMiddleware 呼叫；送出此回應後例外仍重新拋出，供伺服器記錄
        errors = [ErrorDetail(type="internal_error", message="Internal Server Error")]
        return error_response(500, "Internal Server Error", errors)


if __name__ == "__main__":

    class TaskOut(BaseModel):
        task_id: int
        name: str
        status: str

    # 內部紀錄含 worker_token；以 SuccessResponse[TaskOut] 驗證後僅保留對外欄位
    record = {"task_id": 1, "name": "resize-images", "status": "running", "worker_token": "tkn-7f3a"}
    print(SuccessResponse[TaskOut].model_validate(ok(record)).model_dump_json())

    failure = ErrorResponse(
        errors=[
            ErrorDetail(
                field="body.priority",
                type="less_than_equal",
                message="Input should be less than or equal to 10",
            )
        ]
    )
    print(failure.model_dump_json())

# 預期輸出：
# {"success":true,"code":200,"message":"OK","data":{"task_id":1,"name":"resize-images","status":"running"}}
# {"success":false,"code":400,"message":"Bad Request","errors":[{"field":"body.priority","type":"less_than_equal","message":"Input should be less than or equal to 10"}]}
```

### II. response_model Contract（response_model 設計）

`response_model` 宣告路由之輸出契約。路由宣告回應模型（`response_model` 參數或回傳型別註記）時，FastAPI 以之驗證回傳資料、於 OpenAPI 路徑操作加入回應之 JSON Schema、以 Pydantic 將回傳資料序列化為 JSON，並依型別限制與過濾輸出資料。套用原則 I 時，契約為泛型信封 `SuccessResponse[T]`，`T` 為對外模型。

**序列化路徑對照**

| 路由宣告 | 輸出驗證與欄位過濾 | JSON 序列化 | OpenAPI 回應文件 |
| --- | --- | --- | --- |
| 宣告回應模型，未宣告 `response_class` | 執行 | Pydantic 產生 JSON 位元組，以 `application/json` 之 `Response` 直接回應；不經 `jsonable_encoder` 與 `JSONResponse` | 依回應模型自動產生 |
| 宣告回應模型與 JSON 媒體型別之 `response_class` | 執行 | 經 `jsonable_encoder` 轉換後交由 `response_class`，以 Python 標準 JSON 函式庫序列化 | 依回應模型自動產生 |
| 未宣告回應模型（`response_model=None`） | 不執行 | 經 `jsonable_encoder` 轉換後交由 `JSONResponse`（或宣告之 `response_class`） | 不含回應模型之結構 |
| 處理函式直接回傳 `Response` 實例 | 不執行 | 不轉換，原樣送出 | 不自動產生 |

**鐵律**

1. JSON 資料路由預設（原則 IV 情境 A）於裝飾函數宣告 `response_model=SuccessResponse[T]`，且不宣告 `response_class`，使用 Pydantic 直接序列化。
2. 必須以 `responses=ERROR_RESPONSES` 宣告錯誤契約（`400`、`4XX`、`5XX` 皆為 `ErrorResponse`）；`responses` 之模型僅用於產生 OpenAPI 文件，錯誤回應之本體由原則 I 之例外處理器直接回傳之 `JSONResponse` 產生。
3. 錯誤契約必須包含 `4XX`：僅宣告 `400` 時，含參數或請求本體之路由之 OpenAPI 文件仍保留 FastAPI 自動產生之 422（`HTTPValidationError`）項目，與原則 I 之 400 轉換不符；宣告 `4XX` 後不產生該項目（Docker 實測）。
4. 必須明確宣告 `status_code`；處理函式以 `ok()` 組裝信封時，`code` 參數須與 `status_code` 相同（預設皆為 200）。
5. `T` 僅列出允許輸出之欄位，不得以資料庫模型或內部模型作為 `T`。
6. 處理函式之回傳值可為 dict、Pydantic 模型或資料庫模型物件；未宣告於 `T` 之欄位由 FastAPI 依回應模型移除，處理函式不得依賴手動移除內部欄位。
7. 回傳型別與契約不同時，以 `response_model` 參數宣告契約，回傳型別註記標示實際回傳型別；兩者並存時，FastAPI 以 `response_model` 為準。
8. 處理函式不得直接回傳 `Response` 實例；直接回傳時，資料不經驗證、轉換（序列化），亦不自動產生文件，契約僅剩宣告。
9. 需設定回應標頭或 Cookie 時，以注入之 `Response` 參數設定，回傳值維持為資料；FastAPI 將該暫時回應之標頭置入最終回應，回傳值仍依回應模型過濾。
10. 不得使用 `response_model_exclude_none`、`response_model_exclude_unset`、`response_model_exclude_defaults`、`response_model_include`、`response_model_exclude` 參數，以維持原則 I 之固定欄位（例如 `data: null` 不得被移除）；FastAPI 文件指出使用 `response_model_include`、`response_model_exclude` 時，OpenAPI 仍為完整模型之 JSON Schema。
11. 回傳值不符合回應模型時，FastAPI 回應伺服器錯誤而非輸出不正確之資料；實測為拋出 `ResponseValidationError`，經原則 I 之例外處理器輸出 HTTP 500 錯誤信封（Docker 實測）。此情形代表實作違反契約，須修正處理函式，不得放寬模型。

**理由**

+ 契約宣告於裝飾函數，路由之輸出結構可由程式碼審查與 OpenAPI 文件直接確認。
+ 欄位過濾由模型執行，內部欄位（`worker_token`）之排除不依賴處理函式之實作。
+ 泛型信封 `SuccessResponse[T]` 使 OpenAPI 文件呈現包含 `success`、`code`、`message`、`data` 之完整結構（元件名稱 `SuccessResponse_TaskOut_`，Docker 實測）；Pydantic 於參數化泛型模型時於執行期建立子類別並快取。
+ 未宣告 `response_class` 時，FastAPI 以 Pydantic 產生之 JSON 位元組直接回應，不經 `jsonable_encoder` 與 `JSONResponse`；FastAPI 0.130.0 發行說明記載此變更使 JSON 回應效能提升 2 倍以上。
+ 錯誤契約含 `4XX`，OpenAPI 文件之錯誤狀態碼與執行期之錯誤信封一致。

**EXAMPLE**:

### III. response_class Rendering（response_class 設計）

`response_class` 指定路由使用之 Response 類別，決定回應本體之渲染方式與媒體型別（`Content-Type`），並作為 OpenAPI 文件標示之媒體型別。套用原則 I 時，以自訂 `JSONResponse` 子類別於 `render()` 將資料包裝為成功信封，並以 `response_model` 宣告內層資料模型執行驗證與過濾。

**內建類別對照**

| 類別 | 媒體型別 | 以 `response_class` 宣告時之回傳值 | 說明 |
| --- | --- | --- | --- |
| `JSONResponse` | `application/json` | JSON 相容資料 | FastAPI 預設之回應類別 |
| `PlainTextResponse` | `text/plain` | `str` | 純文字；Starlette 對文字型別附加 charset（實測為 `text/plain; charset=utf-8`） |
| `HTMLResponse` | `text/html` | `str` | HTML |
| `RedirectResponse` | — | URL 字串 | 自動設定 `location` 標頭；預設狀態碼 307，可以 `status_code` 變更 |
| `FileResponse` | 未指定時由檔名或路徑推斷 | 檔案路徑 | 非同步串流檔案，含 `Content-Length`、`Last-Modified`、`ETag` 標頭 |
| `StreamingResponse` | 建立實例時指定 | 不適用（處理函式直接回傳實例） | 串流 async generator 或 generator／iterator 之本體 |
| `ORJSONResponse`、`UJSONResponse` | — | 不適用 | 以 orjson、ujson 序列化之 JSON 回應；FastAPI 參考文件標示棄用 |

**鐵律**

1. `response_class` 決定回應之渲染方式與媒體型別，並作為 OpenAPI 文件標示之媒體型別；資料驗證與欄位過濾由 `response_model` 負責。
2. JSON 信封包裝類別必須繼承 `JSONResponse` 並覆寫 `render()`（回傳 `bytes`），`code` 欄位取自 `self.status_code`。
3. 包裝類別僅用於 2xx 成功回應；錯誤回應由原則 I 之例外處理器產生，不得以包裝類別輸出錯誤。
4. 使用包裝類別之路由，`response_model` 宣告內層資料模型 `T`，不得宣告 `SuccessResponse[T]`（避免重複包裝）；回傳資料依 `response_model` 驗證與過濾後，經 `jsonable_encoder` 轉換，再由包裝類別之 `render()` 序列化。
5. 包裝類別改變實際輸出結構，`response_model` 產生之 200 文件為內層模型；必須以 `responses={200: {"model": SuccessResponse[T]}}` 宣告成功回應之文件結構，並合併 `ERROR_RESPONSES`（Docker 實測：200 之 schema 為 `SuccessResponse_TaskOut_`）。
6. 非 JSON 本體使用對應之內建類別，並設定 `response_model=None`；成功本體不套用信封，錯誤回應仍為原則 I 之 `application/json` 錯誤信封。
7. 非 JSON 路由不以 `responses` 之 `model` 宣告錯誤契約：未明確指定媒體型別時，FastAPI 將額外回應視為與主要 `response_class` 相同之媒體型別（例如 `text/plain`），與實際之 `application/json` 錯誤信封不符。此類路由之 OpenAPI 文件保留 FastAPI 自動產生之 422 項目（Docker 實測），實際錯誤回應以原則 I 為準。
8. 處理函式直接回傳 `Response` 實例時，`response_class` 僅用於 OpenAPI 文件，不作用於該回應本體。
9. 路由層級之 `response_class` 優先於 `FastAPI` 或 `APIRouter` 之 `default_response_class`；變更全域預設類別須依原則 IV 評估所有受影響路由。
10. 不得使用 `ORJSONResponse`、`UJSONResponse`；FastAPI 參考文件已標示兩者棄用，並說明宣告回傳型別或回應模型時，FastAPI 由 Pydantic 直接序列化為 JSON 位元組，不需自訂回應類別。

**理由**

+ `code` 取自 `self.status_code`，信封之 `code` 與實際狀態碼同源（Docker 實測：以 `status_code=201` 建立包裝類別實例時，`code` 為 201）；路由變更 `status_code` 時不需同步修改處理函式。
+ 包裝邏輯集中於 Response 類別，處理函式僅回傳資料。
+ FastAPI 文件說明宣告 JSON 媒體型別之 `response_class` 時，回傳資料仍依 `response_model` 轉換與過濾，但不以 Pydantic 序列化，改經 `jsonable_encoder` 轉換後交由該類別以標準 JSON 函式庫序列化；包裝類別之路由保留 `response_model` 以維持驗證與過濾，並列為原則 IV 之非預設情境。
+ FastAPI 文件說明額外回應之媒體型別預設與主要回應類別相同，故非 JSON 路由之錯誤契約不以 `model` 宣告。

**EXAMPLE**:

驗證：Docker 實測（環境版本見〈驗證方式〉），對應檔案 `src/app_response_class.py`。

```python
"""app_response_class.py：response_class 範本（原則 III，套用原則 I 之信封）。

執行：python app_response_class.py（與 envelope.py 置於同一目錄）
服務：uvicorn app_response_class:app --port 8000
相依：pip install "fastapi==0.141.1" httpx2 uvicorn
"""
from typing import Annotated, Any, Literal

from fastapi import FastAPI, HTTPException, Path
from fastapi.responses import JSONResponse
from pydantic import BaseModel

from envelope import ERROR_RESPONSES, SuccessResponse, register_exception_handlers


class EnvelopeJSONResponse(JSONResponse):
    """於渲染階段將回傳資料包裝為成功信封；僅用於 2xx 回應。"""

    def render(self, content: Any) -> bytes:
        # Starlette 於呼叫 render() 前已設定 self.status_code，code 與 HTTP 狀態碼同源
        envelope = {"success": True, "code": self.status_code, "message": "OK", "data": content}
        return super().render(envelope)


class TaskOut(BaseModel):
    """對外模型：作為 response_model，驗證與過濾內層資料。"""

    task_id: int
    name: str
    status: Literal["pending", "running", "done"]
    priority: int


TASKS: dict[int, dict[str, Any]] = {
    1: {"task_id": 1, "name": "resize-images", "status": "running", "priority": 3, "worker_token": "tkn-7f3a"},
}

app = FastAPI(title="response_class template")
register_exception_handlers(app)


@app.get(
    "/tasks/{task_id}",
    response_class=EnvelopeJSONResponse,  # 渲染：成功信封包裝
    response_model=TaskOut,  # 驗證與過濾：內層資料模型（不得宣告 SuccessResponse[TaskOut]，避免重複包裝）
    status_code=200,
    responses={
        200: {"model": SuccessResponse[TaskOut], "description": "OK"},  # 文件：實際輸出之信封結構
        **ERROR_RESPONSES,
    },
)
def get_task(task_id: Annotated[int, Path(ge=1)]) -> dict[str, Any]:
    record = TASKS.get(task_id)
    if record is None:
        raise HTTPException(status_code=404, detail=f"Task {task_id} not found")
    return record  # 經 response_model 移除 worker_token、jsonable_encoder 轉換後，交由 render() 包裝


if __name__ == "__main__":
    from fastapi.testclient import TestClient

    client = TestClient(app)
    for url in ("/tasks/1", "/tasks/0", "/tasks/9"):
        response = client.get(url)
        print(response.status_code, response.headers["content-type"], response.text)

    operation = app.openapi()["paths"]["/tasks/{task_id}"]["get"]
    print(operation["responses"]["200"]["content"])

# 預期輸出：
# 200 application/json {"success":true,"code":200,"message":"OK","data":{"task_id":1,"name":"resize-images","status":"running","priority":3}}
# 400 application/json {"success":false,"code":400,"message":"Request validation failed","errors":[{"field":"path.task_id","type":"greater_than_equal","message":"Input should be greater than or equal to 1"}]}
# 404 application/json {"success":false,"code":404,"message":"Task 9 not found","errors":[{"field":null,"type":"http_error","message":"Task 9 not found"}]}
# {'application/json': {'schema': {'$ref': '#/components/schemas/SuccessResponse_TaskOut_'}}}
```

### IV. Selection Timing（response_model 與 response_class 選用時機）

依回應本體型態、驗證需求與信封包裝位置，選用 `response_model`、`response_class` 或兩者併用；所有情境之錯誤回應皆為原則 I 之錯誤信封。

**情境對照**

| 情境 | 條件 | `response_model` | `response_class` | 成功本體 | JSON 序列化 | 200 文件 | 錯誤契約文件 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A（預設） | JSON 資料回應 | `SuccessResponse[T]` | 不宣告 | 信封，處理函式以 `ok()` 組裝 | Pydantic 直接序列化 | 自動產生 | `ERROR_RESPONSES` |
| B | 本體非 JSON（文字、HTML、檔案、重新導向、串流） | `None` | `PlainTextResponse`、`HTMLResponse`、`FileResponse`、`RedirectResponse`；串流時處理函式直接回傳 `StreamingResponse` 實例 | 非信封 | 不適用 | 依媒體型別自動產生 | 不以 `model` 宣告 |
| C | 需驗證過濾，且由傳輸層統一包裝 | `T` | `EnvelopeJSONResponse` | 信封，由類別包裝 | `jsonable_encoder` 與類別之 `render()` | `responses` 宣告 `SuccessResponse[T]` | `ERROR_RESPONSES` |
| D | 更換 JSON 渲染方式（媒體型別、序列化選項）且需驗證 | `SuccessResponse[T]` | 不改變結構之 `JSONResponse` 子類別 | 信封，處理函式以 `ok()` 組裝 | `jsonable_encoder` 與類別之 `render()` | 自動產生 | `ERROR_RESPONSES` |

**鐵律**

1. JSON 資料回應預設採情境 A；採用其他情境須符合情境對照表之條件欄。
2. 本體非 JSON 時採情境 B；錯誤回應仍為 `application/json` 之錯誤信封，用戶端依 HTTP 狀態碼與 `Content-Type` 區分成功本體與錯誤信封。
3. 情境 C 之 `response_model` 宣告內層資料模型 `T`；`SuccessResponse[T]` 與 `EnvelopeJSONResponse` 不得於同一路由併用，避免重複包裝。
4. 情境 C 之 `T` 須為 Pydantic 模型；列表資料依原則 I 以物件包覆（例如 `TaskPage`）。
5. 情境 D 之自訂類別僅可變更媒體型別或序列化方式，不得變更信封結構。
6. 情境 C、D 宣告 `response_class`，JSON 序列化改經 `jsonable_encoder` 與該類別之 `render()`，不使用 Pydantic 直接序列化；須於路由註解記載採用理由。
7. JSON 路由不得以 `response_model=None` 省略輸出驗證作為效能手段；未宣告回應模型時，FastAPI 以 `jsonable_encoder` 轉換資料，FastAPI 文件指出使用回應模型通常可取得較佳效能。
8. JSON 路由不得以直接回傳 `Response` 實例取代上述組合；需設定標頭或 Cookie 時注入 `Response` 參數（情境 A 範本）。
9. 情境 B 之串流回應須於建立回應實例前完成檢查並拋出例外；回應開始傳送後，`ServerErrorMiddleware` 不再送出錯誤處理器產生之回應，無法改以錯誤信封回應。

**理由**

+ 情境 A 之契約、驗證、過濾與文件由 `response_model` 單一來源產生，宣告與實際輸出一致；FastAPI 文件指出追求最大效能時，使用回應模型且不於裝飾函數宣告 `response_class`。
+ 情境 C 之 `code` 由類別取自狀態碼，處理函式不需呼叫 `ok()`；200 文件須以 `responses` 額外宣告（Docker 實測）。
+ 情境 B 之錯誤回應由例外處理器以 `JSONResponse` 產生，不受路由之 `response_class` 影響（Docker 實測：`/tasks/0/log` 回應 `application/json` 之 400 錯誤信封）。
+ 舊版情境 E（`response_model=None` 併用 `EnvelopeJSONResponse`，以省略輸出驗證降低處理成本）已移除：FastAPI 文件指出未宣告回應模型時資料經 `jsonable_encoder` 轉換，宣告回應模型時由 Pydantic 直接序列化且通常效能較佳，與情境 E 之前提不符。
+ Starlette 之 `ServerErrorMiddleware` 僅於回應尚未開始時送出錯誤處理器之回應（原始碼 `if not response_started`），故串流回應之檢查須於建立實例前完成。

**EXAMPLE**:

驗證：Docker 實測（環境版本見〈驗證方式〉），對應檔案 `src/app_selection.py`。

```python
"""app_selection.py：response_model 與 response_class 選用時機範本（原則 IV）。

執行：python app_selection.py（與 envelope.py、app_response_class.py 置於同一目錄）
服務：uvicorn app_selection:app --port 8000
相依：pip install "fastapi==0.141.1" httpx2 uvicorn
"""
from typing import Annotated, Any, Literal

from fastapi import FastAPI, HTTPException, Path, Response
from fastapi.responses import PlainTextResponse
from pydantic import BaseModel

from app_response_class import EnvelopeJSONResponse
from envelope import ERROR_RESPONSES, SuccessResponse, ok, register_exception_handlers


class TaskOut(BaseModel):
    task_id: int
    name: str
    status: Literal["pending", "running", "done"]
    priority: int


class TaskPage(BaseModel):
    """列表資料以物件包覆（原則 I）。"""

    items: list[TaskOut]
    total: int


TASKS: dict[int, dict[str, Any]] = {
    1: {"task_id": 1, "name": "resize-images", "status": "running", "priority": 3,
        "worker_token": "tkn-7f3a", "log": "resized 120/300 images"},
    2: {"task_id": 2, "name": "encode-video", "status": "pending", "priority": 2,
        "worker_token": "tkn-0002", "log": "waiting for worker"},
}

app = FastAPI(title="response selection template")
register_exception_handlers(app)


def find_task(task_id: int) -> dict[str, Any]:
    record = TASKS.get(task_id)
    if record is None:
        raise HTTPException(status_code=404, detail=f"Task {task_id} not found")
    return record


# 情境 A（預設）：JSON 資料回應 → 僅 response_model，由 Pydantic 直接序列化
@app.get("/tasks/{task_id}", response_model=SuccessResponse[TaskOut], status_code=200, responses=ERROR_RESPONSES)
def get_task(task_id: Annotated[int, Path(ge=1)], response: Response) -> dict[str, Any]:
    response.headers["Cache-Control"] = "no-store"  # 以注入之 Response 設定標頭，保留輸出驗證
    return ok(find_task(task_id))


# 情境 B：本體非 JSON → 僅 response_class，並設定 response_model=None
@app.get("/tasks/{task_id}/log", response_class=PlainTextResponse, response_model=None, status_code=200)
def get_task_log(task_id: Annotated[int, Path(ge=1)]) -> str:
    return find_task(task_id)["log"]  # 找不到時仍輸出 JSON 錯誤信封


# 情境 C：需驗證過濾，且由傳輸層統一包裝 → 兩者併用，並以 responses 宣告 200 文件
@app.get(
    "/tasks",
    response_model=TaskPage,  # 內層資料模型；不得宣告 SuccessResponse[TaskPage]
    response_class=EnvelopeJSONResponse,
    status_code=200,
    responses={200: {"model": SuccessResponse[TaskPage], "description": "OK"}, **ERROR_RESPONSES},
)
def list_tasks() -> dict[str, Any]:
    records = list(TASKS.values())  # 含 worker_token、log，由 response_model 移除
    return {"items": records, "total": len(records)}


if __name__ == "__main__":
    from fastapi.testclient import TestClient

    client = TestClient(app)
    for url in ("/tasks/1", "/tasks/1/log", "/tasks", "/tasks/9/log"):
        response = client.get(url)
        print(response.status_code, response.headers["content-type"], response.text)
    print(client.get("/tasks/1").headers["cache-control"])

# 預期輸出：
# 200 application/json {"success":true,"code":200,"message":"OK","data":{"task_id":1,"name":"resize-images","status":"running","priority":3}}
# 200 text/plain; charset=utf-8 resized 120/300 images
# 200 application/json {"success":true,"code":200,"message":"OK","data":{"items":[{"task_id":1,"name":"resize-images","status":"running","priority":3},{"task_id":2,"name":"encode-video","status":"pending","priority":2}],"total":2}}
# 404 application/json {"success":false,"code":404,"message":"Task 9 not found","errors":[{"field":null,"type":"http_error","message":"Task 9 not found"}]}
# no-store
```
