# Application Interface design specification

## 核心原則

本應用程式介面之設計與開發，須遵循以下核心原則。

### I. 對外服務介面原則
應用程式介面須以網際網路應用程式介面 (API) 形式提供服務，供遠端主機透過網路調用。所有服務能力須可經由網路請求存取。

**理由**：以網路介面統一暴露服務，使遠端主機得以透過標準網路請求存取，無須仰賴特定用戶端程式。

**EXAMPLE**:
```bash
curl http://[host-name]/api/exec
```

### II. Python 與 FastAPI 框架原則
伺服器端程式語言須採用 Python，軟體框架須採用 FastAPI。

**理由**：FastAPI 基於 Python 型別提示提供請求驗證與自動化文件產生能力。

**EXAMPLE**:
```python
# app/api/server/main.py
from fastapi import FastAPI
from fastapi import __version__ as fastapi_version

app = FastAPI()

@app.get("/")
def show_fastapi_information():
    return {"Server": "FastAPI Server", "Version": f"{fastapi_version}"}
```

### III. Docker 容器化與精簡映像原則
執行環境須採用 Docker，容器基底映像檔須使用 slim 版本。

**理由**：slim 版本映像檔可縮減映像檔體積。

**EXAMPLE**:
```dockerfile
FROM python:slim

WORKDIR /app/api

COPY . .

ENTRYPOINT ["./docker-entrypoint.sh"]
```

### IV. 專案結構標準化原則
應用程式介面專案根目錄為 `app/api`；其下 `server` 目錄須包含 `routes`（路由目錄）、`service`（共用服務目錄）與 `main.py`（伺服器進入點）；執行環境進入點腳本須置於 `app/api/docker-entrypoint.sh`。

**理由**：標準化目錄結構使路由、共用服務與進入點程式碼各司其職。

**EXAMPLE**:
```
app/api
├── server
│   ├── routes
│   ├── service
│   └── main.py
└── docker-entrypoint.sh
```

### V. 路由目錄化與模組掛載原則
每個路由須以獨立目錄形式結構化。根路由 (`/`) 須直接於伺服器進入點定義；子路由須以套件形式，透過 `app.mount()` 掛載至指定路徑。

**理由**：目錄化路由與模組化掛載使各路由服務相互獨立。

**EXAMPLE**:
```python
# 根路由
from fastapi import FastAPI
from fastapi import __version__ as fastapi_version

@app.get("/")
def show_fastapi_information():
    return {"Server": "FastAPI Server", "Version": f"{fastapi_version}"}
```
```python
# main.py，子路由掛載
from routes import asa

app = FastAPI()
app.mount("/asa", asa.module)
```
